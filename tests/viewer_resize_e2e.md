# Viewer resize and input regression

`viewer_resize_e2e.rb` drives the production `kwin-mcp` stdio entrypoint. It starts an outer isolated desktop for the viewer and an inner isolated session containing a full-screen C GTK test application. Both sessions use empty private homes. Host browser profiles and host windows are outside this test.

## Build

From the repository root, build the production binaries and the C fixtures:

```bash
cargo build --locked --bins
bash tests/build_viewer_fixtures.sh /path/to/private-bin
```

The fixtures require GTK 4, Wayland client development files, `wayland-scanner`, and the Plasma `fake-input.xml` protocol. They use the system XML, falling back to the already-locked `wayland-protocols-plasma` Cargo dependency. Set `KWIN_MCP_FAKE_INPUT_XML` to use another private copy.

Copy `target/debug/kwin-mcp`, `target/debug/kwin-viewer`, and the two fixture binaries into one private run directory on the KDE host. Keep the source script available at a path under `/home`; session `/tmp` is private. Keep the run directory outside the repository so generated evidence stays out of source control.

## Run

```bash
KWIN_MCP_E2E_BIN_DIR=/path/to/private-bin \
  ruby tests/viewer_resize_e2e.rb /path/to/private-run-directory
```

The fixture uses the normal session window rule. Since #315, KWin applies maximize when each window opens and permits resizing afterward. It can also use a short writable host path supplied as `KWIN_MCP_E2E_TMPDIR` for each server’s `TMPDIR`; this avoids Unix-socket path limits and lets the run avoid a full `/tmp` quota. It supplies `/run/user/<uid>` and its D-Bus address to each private server, and `viewer_open` receives the outer isolated Wayland socket.

The GTK fixture application records the mouse-button events it receives in `events.log`. The regression sends a mouse click and then a touch sequence after each resize, and checks the fixture’s recorded pixels for both inputs. The viewer does not add touch-specific logging for the regression.

The runtime also needs `ruby` and ImageMagick `magick` on the KDE host. The test performs these real operations:

1. `session_start` for each production stdio server, then `launch_app` and `viewer_open` for the inner session.
2. Drag the viewer’s bottom edge, then a horizontal edge, through real Meta+right-button input in the outer isolated KWin.
3. Query the resulting geometry through `window_list`, capture through `screenshot`, and verify all four picture corners contain the expected colors, with no bars.
4. Click through the outer session’s `mouse_click` at a known viewer position. A persistent authenticated fake-input client is connected before the viewer opens so its Wayland seat advertises touch; send touch down/up sequences through that protocol after each resize. Verify the C application in the inner session received the expected pixels within two pixels.
5. Export the fixture application’s `events.log` and the viewer log used to diagnose any rejected resize request, then call `session_stop` on both sessions.

The private run directory contains JSON-RPC logs, requested and resulting geometry, screenshots, fixture application input coordinates, viewer resize requests, and the sizes returned by `request_inner_size`.

The normal result requires the same 4:3 ratio as the 800×600 session after both resizes, within one pixel of integer rounding. Under #250’s compositor exception, a differing ratio is reported as a limitation only when the viewer log shows `request_inner_size` returning exactly that measured, uncorrected geometry. Fixture input and corner-color assertions still must pass. A mismatch without that evidence fails the test.

The fixture’s exported `events.log` is the evidence that input reached the session application. Screenshots, geometry, and logs are generated by each run and should remain in the private run directory rather than being committed.
